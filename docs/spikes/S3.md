Run everything (no network, dummy keys, local stub server only):

- `bench/spikes/S3/http_clients.py`: asyncio HTTP/1.1 keep-alive stub that speaks OpenAI `/chat/completions`, Anthropic `/v1/messages` and Ollama `/api/chat` (JSON and streaming) and counts concurrent TCP connections (`max_open_tcp`) and in-flight requests. ## 1. Shared `http_async_client` with limits

### Question
Through `init_chat_model` kwargs, does each integration use the same `httpx.AsyncClient` instance, and do its `Limits` apply?

### Finding that changes the premise: two httpx libraries
`openai>=3` and `anthropic` 2.x run on `httpx2`, not `httpx` (`openai/_base_client.py:37`, `anthropic/_base_client.py:40`); `ollama` runs on `httpx` (`ollama/_client.py:43`). The OpenAI SDK accepts either (`openai/_base_client.py:1652-1660`, checks `is_httpx2_async_client` or `is_legacy_httpx_async_client`). The Anthropic SDK rejects `httpx` objects with a `TypeError` (`anthropic/_base_client.py:160-166`, `:1863`). Both SDK defaults are `Limits(max_connections=1000, max_keepalive_connections=100)` (`openai/_constants.py:9`, `anthropic/_constants.py:12`).

### Results

Baseline without a shared client, every provider: `max_open_tcp=8` for 8 concurrent calls (no effective limit).

**langchain-openai (default base URL): PASS.** `init_chat_model("gpt-4o-mini", model_provider="openai", http_async_client=c, timeout=60, max_retries=2)`: `root_async_client._client is c` -> `True`; SDK `timeout=60.0`, `max_retries=2` still apply. No request sent (no network); the limit is proven on the base_url path below, which uses the same SDK client code (`langchain_openai/chat_models/base.py:1528-1547`).

**OpenAI-compatible `base_url`: PASS.** Two instances (different model names) sharing one client: `same_instance=True`; `Limits(2)` -> `max_open_tcp=2 max_inflight=2`, for both `ainvoke` and `astream`, with an `httpx2.AsyncClient` and with a legacy `httpx.AsyncClient`.

**langchain-anthropic: FAIL, alternative PASS.** `ChatAnthropic` has no `http_async_client` field. `init_chat_model(..., http_async_client=c)` warns "`http_async_client` was transferred to `model_kwargs`" and the first call fails: `TypeError: AsyncMessages.create() got an unexpected keyword argument 'http_async_client'`. Its default async client is an `lru_cache`d httpx2 client per `(base_url, timeout, proxy)` (`langchain_anthropic/_client_utils.py:65-80`, used at `chat_models.py:1781-1794`), already shared across instances but with the SDK's 1000-connection pool.
Alternative (smallest that works): pre-fill the `_async_client` `cached_property` after `init_chat_model`:

```python
model.__dict__["_async_client"] = anthropic.AsyncClient(
    **model._client_params, http_client=shared_httpx2_client
)
```

Result: `same_instance=True`, SDK `timeout=60.0 max_retries=2` kept (they come from `_client_params`, `chat_models.py:1745-1764`), `Limits(2)` -> `max_open_tcp=2` for `ainvoke` and `astream`; `model_copy()` keeps the seeded client. Passing an `httpx.AsyncClient` raises the `TypeError` above. This relies on two private members (`_async_client`, `_client_params`); a unit test asserting `model._async_client._client is shared` turns a rename into a CI failure instead of a silent fallback to the unlimited pool. A delegating `BaseChatModel` wrapper was not needed.

**langchain-ollama: FAIL, alternative PASS.** `ChatOllama` has no `http_async_client` field and pydantic's default `extra="ignore"` drops it with no warning: built fine, `same_instance=False`. Every instance builds its own `httpx.AsyncClient` (`langchain_ollama/chat_models.py:944-958`, `ollama/_client.py:116-122`). `async_client_kwargs={"limits": Limits(2)}` is per instance: two instances -> `max_open_tcp=4`.
Alternative: share one `httpx.AsyncHTTPTransport(limits=...)` (the pool lives in the transport) through `async_client_kwargs={"transport": transport, "timeout": timeout_s}`: `same_transport=True`, `Limits(2)` -> `max_open_tcp=2` for `ainvoke` and `astream`. httpx uses a given transport as-is and ignores `limits` then (`httpx/_client.py:1442-1443`). `ChatOllama` has no `timeout` or `max_retries` field (dropped silently); the timeout must go in `async_client_kwargs` (`timeout=Timeout(timeout=60)` verified), and there are no SDK retries. Caveat: `AsyncClient.aclose()` closes its transport (`httpx/_client.py:1985`), so nothing may call `model._async_client.close()`; only the owner closes the transport.

## 2. Agent name in callback metadata

### Question
Which callback and metadata key carries `create_agent(name=...)`, including a subagent called through a tool and a node-subgraph?

### Results: PARTIAL
- `create_agent` sets `config["metadata"]["lc_agent_name"] = name` on the compiled graph via `.with_config` (`langchain/agents/factory.py:1899-1902`). It arrives in `on_chat_model_start(..., metadata=...)`.
- `on_llm_end` receives no `metadata` and no extra kwargs (`on_llm_end_kwargs=[]`); usage is in `response.generations[0][0].message.usage_metadata`. A usage callback must map `run_id` -> agent in `on_chat_model_start` and read it back in `on_llm_end`.
- Metadata merges last-writer-wins and the incoming (parent) config wins over the bound one (`langchain_core/runnables/base.py:5990-5992`, `config.py:399-419`). Observed `lc_agent_name` per model call:

| Case | Inner model call | Correct? |
|------|------------------|----------|
| Agent invoked directly | `researcher` | yes |
| Agent node in a plain `StateGraph` | `researcher`; plain node calling a model: `None` | yes |
| Subagent in a tool, tool calls `sub.ainvoke(x)` without config | `researcher` | yes |
| Subagent in a tool, tool passes its `RunnableConfig` to `sub.ainvoke(x, config)` | `boss` | no |
| Plain graph with an agent node, run inside a named agent's tool | `boss`; plain node also `boss` | no |

Passing the tool's config is the correct way to propagate callbacks, recursion limits and tags, so `as_tool` will likely do it; `lc_agent_name` is not reliable for attribution.

- Working key: put the name in the model instance's own `metadata` (local, non-inheritable callback metadata, applied after inherited metadata: `langchain_core/language_models/chat_models.py:1076-1083`, `callbacks/manager.py:2498-2499`): `model.model_copy(update={"metadata": {"graph_agent_agent": name}})` passed to `create_agent`. Observed `graph_agent_agent` = `researcher` for the inner call and `boss` for the outer calls in every case, including both failing rows; a plain node's model call gets `None` (-> `""`, matching design.md §9). `model_copy()` keeps the shared HTTP client for openai and seeded anthropic (`model_copy keeps client: True`).

## 3. `stream_usage`

- **openai / OpenAI-compatible: required.** langchain-openai enables `stream_usage` by default only when no `base_url`, no `OPENAI_BASE_URL`, no proxy and no `http_client`/`http_async_client` are set (`langchain_openai/chat_models/base.py:1435-1454`). Without the shared client: `stream_usage=True`; with it, even on the default URL: `None`. Streaming against the stub with `None`: no `stream_options` sent, `usage_metadata=None`; with `stream_usage=True`: `stream_options={'include_usage': True}`, usage `3/1/4`.
- **anthropic: not needed.** Field default `stream_usage: bool = True` (`langchain_anthropic/chat_models.py:1469`); streamed usage `3/1/4`, read from the cumulative `message_delta.usage` (`chat_models.py:2494-2497`, `anthropic/types/message_delta_usage.py`).
- **ollama: not applicable.** No `stream_usage` field; `ChatOllama` always streams internally (`request stream=True` even for `ainvoke`) and reports usage from the final `done` chunk: streamed and `ainvoke` usage `3/1/4`.

## Impact on design

1. §8 table, row "LLM provider concurrency", Mechanism.
   - Before: `One shared httpx.AsyncClient per provider with connection limits passed to the integration (open check per integration)`
   - After: `One shared connection pool per provider with Limits(max_connections): openai and OpenAI-compatible get an httpx2.AsyncClient as http_async_client; anthropic gets an httpx2.AsyncClient seeded into the model's SDK client (no kwarg in langchain-anthropic 1.7.10); ollama gets a shared httpx.AsyncHTTPTransport through async_client_kwargs (S3)`
2. §9 "Kept rules".
   - Before: `` `stream_usage` on for OpenAI-compatible providers so streamed runs report tokens. ``
   - After: `` `stream_usage=True` for every `openai` profile, api.openai.com included (a shared `http_async_client` turns off langchain-openai's default); anthropic streams usage by default and ollama always reports it. Ollama has no `timeout`/`max_retries` fields: the timeout goes into `async_client_kwargs`, retries are not supported. ``
3. §9 "Usage ledger" paragraph.
   - Before: `a per-run callback aggregates usage_metadata per (model, agent);`
   - After: `a per-run callback aggregates usage_metadata per (model, agent); the agent is read in on_chat_model_start from the metadata key graph_agent_agent, which build_agent sets on a model_copy of the profile model (local callback metadata, so the innermost agent wins); lc_agent_name is not used because a parent agent's value overrides it when the subagent runs with the parent's config (S3);`
4. §7 first paragraph.
   - Before: `create_agent(model=ctx.model(spec.profile), tools=...`
   - After: `create_agent(model=ctx.model(spec.profile) tagged with the agent name (see §9 Usage ledger), tools=...`
5. §14 "Open checks": remove the rows "Each provider integration accepts a shared `http_async_client` ..." and "`create_agent(name=...)` exposes the agent name in callback metadata" (resolved in `docs/spikes/S3.md`).
6. §2 core dependencies (orchestrator decision, not edited here): `llm.py` will import `httpx2` directly; today it is only transitive (via `mcp`, `openai`, `anthropic`). Declare `httpx2>=2.16,<3` in `packages/core/pyproject.toml`.

## Impact on dependent tasks

- **T08**: per provider: `openai` -> `http_async_client=<httpx2.AsyncClient(limits=...)>` plus `stream_usage=True` always; `anthropic` -> build with `init_chat_model` (no client kwarg) then seed `_async_client` with `anthropic.AsyncClient(**model._client_params, http_client=<httpx2.AsyncClient>)`, with a `shortcut:` comment (private API, revisit when langchain-anthropic adds a client kwarg) and a unit test asserting the identity; `ollama` -> `async_client_kwargs={"transport": <httpx.AsyncHTTPTransport(limits=...)>, "timeout": timeout_s}`, no `max_retries` (reject or document it for ollama profiles). `aclose()` closes the shared clients/transports; models are never closed individually. Building a model does no I/O (verified: openai built with no network).
- **T30**: `build_agent` passes `model.model_copy(update={"metadata": {**(model.metadata or {}), "graph_agent_agent": spec.name}})` to `create_agent` (keeps the shared client); `as_tool` may pass the tool's `RunnableConfig` to the subagent, attribution survives it. Export the key as one named constant shared with T32.
- **T32**: `UsageCallback` records `metadata.get("graph_agent_agent", "")` per `run_id` in `on_chat_model_start` and reads it back in `on_llm_end` (which gets no metadata); usage from `response.generations[0][0].message.usage_metadata`. Do not use `lc_agent_name`.
